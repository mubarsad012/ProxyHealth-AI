# ProxyHealth AI — API Contract (backbone document)

Status: **authoritative**. The Pydantic v2 models in `apps/api/proxyhealth_api/contracts/` are the single source of truth; this document describes them field by field so that WP0 can write them and every other agent can code against them before they exist. `scripts/export_openapi.py` writes `apps/api/openapi.json` (committed; snapshot-tested), and `apps/mobile/src/api/schema.d.ts` is generated from that file with `openapi-typescript`. If this document and the models disagree, fix one and say which.

Decisions this contract implements: `docs/DECISIONS.md` D-01…D-32 (tier gate, consent header, caps, quotation contract, counts-only feedback, JSON-only bodies, the `openai_compat` provider and its tiers).

Revision 2026-10-04 (Phase 3, D-32; code-authoritative, `openapi.json` regenerated by API-PROVIDER): `DataUseTier` gains `local` and `attested`, `Provider` gains `openai_compat` (§1); `ServerConfig` gains `ai_model_label`, `ai_vendor_name` and `client_timeouts` (§3.2), and the client time limits of §0 now come from `client_timeouts`; the chat `AnalysisContext` (§3.7) and `ResourceMatchRequest.institutions_as_written` (§3.8) carry caps in the contract itself; `provider_not_configured` and `payload_too_large` gain `openai_compat` cases (§0.1). `CONTRACT_VERSION` stays `1` (additive change; D-32 records why).

Revision 2026-09-27 (consistency pass; WP0 implements these in the models before M0): `AnalyzeRequest.pages` is 0–12 with a model validator requiring ≥ 1 page unless `demo_sample_id` is set; `include_page_thumbnails` defaults to `false` (client sets `true` for PDFs); `TroubleshootResult` gains `safety: Safety`; `Resource.phone`/`tty` accept E.164 or N11/short codes; model-output schemas gain `LanguageResolveOut` and `RewriteOut` (§4). Example values (`resources_loaded`, versions, `why_keys`) were aligned with `docs/RESOURCE_DB.md` and `docs/DOCUMENT_TAXONOMY.md`.

## 0. Conventions

- **Base URL**: `EXPO_PUBLIC_API_URL` (dev `http://127.0.0.1:8000`). All versioned routes live under `/v1`; `/health` is unversioned.
- **Content type**: every request and response body is `application/json; charset=utf-8`, except `POST /v1/quicksheet/pdf` (returns `application/pdf`) and `GET /v1/demo/fixtures/{id}/pages/{n}` (returns `image/png`). Binary inputs are base64 strings inside JSON (`data_base64`). There is **no** multipart endpoint in v1 (D-21).
- **Contract version**: header `X-Contract-Version: 1` on every response; `ServerConfig.contract_version` carries the same integer. Breaking changes bump it and the `/v2` prefix. The Phase 3 additions (new enum values, new `ServerConfig` fields with defaults, request caps) were judged additive and kept version `1`: the only client is generated from the same `openapi.json`, and no build has been released (D-32).
- **Authentication**: none in v1. Header `X-App-Token` is **reserved**: the server accepts and ignores it today; when `APP_TOKEN` is set in the environment, requests without a matching token receive `401 unauthorized` (only CORS preflight `OPTIONS` is exempt; the 401 envelope carries CORS headers — CL-023). Clients send it whenever `EXPO_PUBLIC_APP_TOKEN` is configured.
- **Request headers**

| Header | Required on | Meaning |
|---|---|---|
| `X-Request-Id` | any (optional) | Client-generated UUID v4; echoed. Server generates one if absent. |
| `X-Install-Id` | any (optional) | Random UUID generated on device; HMAC-hashed server-side for rate limiting only (D-08). |
| `X-Consent-Version` | `POST /v1/analyze`, `/v1/troubleshoot`, `/v1/chat` | The `consent_version` the user accepted (from `ServerConfig`). Missing/stale → `428 consent_required`. Exempt only when `demo_sample_id` names a known bundled fixture; an unknown id is gated like no id (`428`, or `403` on `unpaid`/`mixed`; CL-031). On `unpaid`/`mixed` a known-fixture request that still carries typed text (every `/v1/chat` request, or a troubleshoot with a non-blank `user_goal`) is gated like a real paper too (`ServerConfig.features.chat` is `false` there). |
| `X-App-Token` | any (reserved) | See Authentication. |
| `If-None-Match` | `GET /v1/language-packs/{tag}` | ETag revalidation → `304`. |
| `Accept-Language` | any (optional) | Used only to pick `user_message` language for error copy when the client sends no `target_language`. |

- **Response headers**: `X-Request-Id`, `X-Contract-Version`, `X-Data-Use-Tier` (`paid|unpaid|mixed|demo|none|local|attested`), `Retry-After` (seconds; on every 429 and 503), `ETag` (language packs).
- **Timeouts**: the client waits `ServerConfig.client_timeouts` seconds per request kind (§3.2), clamped to 5 s – 30 min (`api/client.ts` `timeoutFor`). The defaults are 120 s for `/v1/analyze`, 60 s for `/v1/troubleshoot` and `/v1/language-packs` POST, 30 s for `/v1/chat` and 30 s otherwise; the client uses these fixed values until `/v1/config` has answered. With `AI_PROVIDER=openai_compat` the server raises the four model-calling limits to `FAILOVER_DEADLINE_S + OPENAI_COMPAT_TIMEOUT_S + 15` (a local model can take minutes; D-32).
- **Idempotency**: all POST endpoints are stateless and safe to retry after a network failure; nothing is stored server-side except language-pack cache, key-pool state and feedback counters.
- **Nothing is persisted**: request bodies are processed in memory and released; no temp files; access logs strip bodies (D-08).

### 0.1 Error envelope (every non-2xx response)

Model `ErrorResponse { error: ErrorBody }`

| `ErrorBody` field | Type | Description |
|---|---|---|
| `code` | `ErrorCode` (enum) | Machine-readable code (table below). |
| `message` | `str` | English, for developers; never contains user content. |
| `user_message_key` | `str` | i18n key the client renders from the language pack, e.g. `err.quota_exhausted`. |
| `retry_after_seconds` | `int \| null` | Present on 429/503; mirrors the `Retry-After` header (30 when the raiser gave no value — CL-031(c)). |
| `key_exhausted` | `bool` | `true` only when every upstream key slot for the needed tier is cooling/exhausted (so the client offers offline options and "Try a sample"). |
| `request_id` | `str` | Correlation id (also in `X-Request-Id`). |
| `details` | `dict[str, str \| int \| bool] \| null` | Small, content-free extras (e.g. `{"block_reason": "spii"}`, `{"max_pages": 12}`). |

| `ErrorCode` | HTTP | When |
|---|---|---|
| `invalid_request` | 400 | Pydantic validation failure, bad base64, unknown tag. The `message` names the failing field path; path segments that are not contract field names or indexes are redacted as `<extra>` (CL-031(b)). |
| `too_many_pages` | 400 | > `limits.max_pages` images, or images mixed with a PDF. |
| `pdf_too_long` | 400 | PDF > `limits.max_pdf_pages` pages. |
| `unauthorized` | 401 | Missing/invalid `X-App-Token` (when enforced) or `X-Admin-Token`. |
| `unpaid_tier_real_documents_disabled` | 403 | Tier is `unpaid`/`mixed` (Gemini, or `openai_compat` with `OPENAI_COMPAT_DATA_TIER=unpaid`) and the request is not a known demo fixture, or it is one that carries typed text (every `/v1/chat`, a non-blank troubleshoot `user_goal`; `middleware._carries_client_text`; D-01). The same gate covers `attested` outside `ENV=development` (`Settings.samples_only`; that tier cannot boot there; D-32). |
| `not_found` | 404 | Unknown resource/fixture/pack tag. |
| `pack_version_mismatch` | 409 | Client base pack hash ≠ server base pack hash. |
| `payload_too_large` | 413 | Body > `limits.max_request_bytes`, a page > `limits.max_page_bytes`, or PDF > `limits.max_pdf_bytes`. On `openai_compat` also: a page with too many pixels to decode safely, or an upstream `413` ("The pages are too large for this AI server."). |
| `unsupported_media_type` | 415 | MIME not in the allow-list: a body `mime_type` outside `PageMimeType` (answered by `errors.py`, not as a 400), or bytes whose magic number does not match the declared type (`analysis/uploads.py`) — CL-031(a). On `openai_compat` also: a page the server cannot decode to send as an image (for example HEIC without a codec). |
| `content_blocked` | 422 | Upstream blocked the generation (`details.block_reason ∈ safety, spii, prohibited_content, recitation, blocklist, other`). Never retried on another key. |
| `language_unresolved` | 422 | Typed language could not be resolved and no `x-` fallback was possible (empty/garbage query). |
| `consent_required` | 428 | `X-Consent-Version` missing or older than `ServerConfig.consent_version`. |
| `rate_limited` | 429 | Per-install or per-IP-class bucket exceeded (`key_exhausted=false`). `details = {window: "hour"\|"day"\|"minute", limit: int, bucket: "install"\|"ip_class"}` (D-08; `ratelimit.py`). |
| `quota_exhausted` | 429 | All upstream slots for the tier are unavailable (`key_exhausted=true`). |
| `internal` | 500 | Unexpected server error. |
| `model_output_invalid` | 502 | Model output failed schema after the single-call → two-call fallback. On a loopback `openai_compat` endpoint also when less than 120 s of `FAILOVER_DEADLINE_S` is left to start that fallback or the injection re-run (`details.reason` `injection_rerun`; AI_PROMPTS §11.8) (`user_message_key` `err.ai_too_slow`; `analysis/compat_runtime.py`). |
| `provider_not_configured` | 503 | `AI_PROVIDER=gemini` with no usable slots at boot (only reachable in `ENV=development`). On `openai_compat`: the loopback AI server refuses the connection ("Local AI server is not running.", `Retry-After: 30`), or the endpoint answers `404` for the model ("The AI model is not available on the AI server.", `Retry-After: 60`) (D-32). |
| `upstream_unavailable` | 503 | Upstream 5xx after bounded retries. On `openai_compat` also a call whose time budget ran out: `user_message_key` is `err.ai_too_slow` when a paper-reading task ran on a loopback endpoint, or `err.ai_busy` (`Retry-After: 60`) when at least a third of the budget went on waiting behind another request; hosted endpoints and other tasks keep `err.upstream_unavailable` (`ai/slow_errors.py`; ARCHITECTURE §6.1). The envelope still carries `retry_after_seconds`, but the app shows no retry countdown for `err.ai_too_slow`, because a retry takes as long again. |

Example:
```json
{
  "error": {
    "code": "quota_exhausted",
    "message": "All 3 key slots for tier 'pro' are cooling down; earliest retry in 240 s.",
    "user_message_key": "err.quota_exhausted",
    "retry_after_seconds": 240,
    "key_exhausted": true,
    "request_id": "5d0d8b3e-3a3f-4b7a-9d8b-0c9e1f2a3b4c",
    "details": {"tier": "pro", "slots_total": 3, "slots_cooling": 3}
  }
}
```

## 5. OpenAPI and TypeScript generation

- `apps/api/.venv/bin/python apps/api/scripts/export_openapi.py` → `apps/api/openapi.json` (deterministic key order). `tests/contract/test_openapi_snapshot.py` fails if the committed file is stale.
- `apps/mobile`: `npm run gen:types` is changed to `openapi-typescript ../api/openapi.json -o src/api/schema.d.ts` (file input; no server needed). The client (`src/api/client.ts`) imports `components["schemas"]["AnalysisResult"]` etc.; no hand-written duplicates of contract types are allowed.
- `ErrorResponse` is declared as the response model for every 4xx/5xx in `responses={...}` so the generated types include it.
- **Field-name rule (buildability pass 2026-09-27).** Every Pydantic field name in `contracts/**` is a valid Python identifier in `snake_case` exactly as written in the tables above; no `alias`, `populate_by_name` or camelCase conversion anywhere, so the JSON wire names, the generated TypeScript property names and the Python attribute names are identical. Request models use `model_config = ConfigDict(extra="forbid")` (an unknown field is a `400 invalid_request`, which catches client typos early); response models keep Pydantic's default. Enum *values* are the lowercase snake_case strings listed in §1 (`PackTier` is an `IntEnum`). `tests/contract/test_openapi_snapshot.py` also asserts that no property name in `openapi.json` contains an uppercase letter or a hyphen.
